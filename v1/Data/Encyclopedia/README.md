## 계절·대표 지역 칸 (v0.95, 사장님 지시 2026-11-02)

`reviewed.json` 항목의 선택 칸 `season`·`representative_region` 을 생성기가 검사해 `catalog.json` 음식에 그대로 넣는다. 앱 화면은 예전부터 이 이름의 칸을 읽는다(계절 필터·지역 필터·음식 쪽 '한눈에').

- `season`: 주로 먹고 많이 파는 때. `봄`·`여름`·`가을`·`겨울` 을 `·` 로 잇거나, 연중 흔하면 `사계절`. 가게마다 판매 기간이 다르며 판매 보장이 아니다.
- `representative_region`: 발상지·대표 지역 도도부현(앱 `ENC_REGIONS` 의 한국어 이름, 띄어쓰기로 여러 개) 또는 특정 지역과 묶이지 않으면 `전국`. '이곳에서만 판다'는 뜻이 아니다.
- 지역 필터에서 `전국` 음식은 '확인 필요'로 모으지 않고 뺀다. 계절 필터에서 `사계절` 음식은 뺀다(그 계절 음식만 보임, 사장님 지시 2026-11-02). 칸이 없는 옛 카탈로그·입력기 원고는 예전처럼 동작한다.
- 값은 편집 판단(공공·백과 자료의 지역·계절 설명 대조)이며 실제 판매 조사가 아니다. 현재 사계절 139개, 계절이 있는 음식 12개(여름 6·가을·겨울 4·봄·가을 1·겨울 1), 전국 99개·특정 지역 52개.

## 공개 상태와 확인 범위

**라멘 외 81개는 `초안 · 추후 수정` 상태**다. v0.3 당시 사용자 결정 “앱에 넣고 추후 수정”에 따라 공개했다. 당시 Claude 확인은 필수 칸과 출처 링크 형식이며, 모든 음식 사실·가게별 판매·가격·알레르기·사진 권리의 일괄 검증 완료를 뜻하지 않는다. 항목별 `review_scope_ko`와 별도 사진 출처를 확인한다.

국물 라멘은 v0.22에 기본 소개를 확인해 연결했다. `reviewed.json`이라는 파일명이나 `reviewed_on` 날짜만으로 전체 사실 검수 완료를 추정하지 않는다.

- v0.22 규동 기본 소개: [요시노야 재료 소개](https://www.yoshinoya.com/kodawari/)와 [메뉴 소개](https://www.yoshinoya.com/menu/gyudon/gyu-don/)의 재료·별도 메뉴 문맥을 확인한 이력. 한 브랜드의 구성은 모든 가게의 보장이 아니다. 현재 규동 본문은 v2.0 원고를 쓰며 이전 근거와 고정 ID를 보존한다.
- v0.22 국물 라멘: [NAVITIME 안내](https://japantravel.navitime.com/en/area/jp/guide/NTJhowto0068-en/)의 국물/면·양념·제공 방식 구분을 확인한 이력. 현재 가격·영업·유행을 확인한 자료가 아니다.
- v0.57: 근거 없는 긍정 추천과 알레르기 단정 표현을 교정했다. 새 감각 수치·만족 확률을 만들지 않는다.

v0.59의 21개 기본 음식·길잡이는 공식 관광·농림수산성·생산자 등 관련 자료 발췌를 대조한 별도 편집 원고다. 기존 81개 초안을 이번 작업에서 전수 재검증한 것은 아니다. 감각 표현은 정성적 소개이며 실제 측정값이 아니다. 새 원고·근거의 범위는 [구현 보고서](../../docs/design/encyclopedia_v2/IMPLEMENTATION_V059.md)를 참고한다.

## 사진

현재 **103항목 중 41항목에 사진 연결, 62항목 미연결**이다.

- 40항목: `enc_<원본 id>.jpg`, 출처는 `photo_credits.json`. v0.32 작업 기록상 CC0·퍼블릭 도메인 자료를 선정하고 음식 일치·인물 여부를 확인했다. 이번에 권리·내용을 재검수한 것은 아니다.
- 국물 라멘 1항목: 사용자 제공 `cat_noodle.jpg`, 출처 기록은 `Assets/Home/README.txt`.
- 규동은 현재 `enc_gyudon.jpg`가 연결되어 있다. 과거의 “규동 사진 준비 중”은 현재 상태가 아니다.
- 음식 예시 사진이며 실제 가게 메뉴 사진으로 취급하지 않는다. `catalog.json.images`가 빈 배열이어도 본문 HTML에 사진을 넣는 구조이므로 사진 0개라는 뜻이 아니다.

앱 URL `/Assets/Home/...`는 유지하고 배포 파일은 `resources/Assets/Home/...`에서 읽는다.

## 읽기 경로·분류·사용자 기록

개발판은 호환 가능한 기존 MSBData 원고를 우선 읽으며, 읽을 수 없거나 목차가 없으면 기본 카탈로그를 읽는다. 출시판은 기본 카탈로그를 읽는다. 화면 코드에는 두 경로 모두 사용할 수 없을 때 기존 분류 안내로 대체하는 경로가 있다. 단, **외부 Data 전체 검증 실패 시에는 앱 복구 화면에서 먼저 차단**되므로 이를 정상 사용 가능한 상태로 설명하면 안 된다.

11분류는 적용됐다. 원본 13분류 중 간편 밥·도시락은 밥·덮밥에, 빵·샌드위치는 디저트·화과자·빵에 합쳤다. 기본 카탈로그의 5탐색 경로를 연결했다. 비교 6개·주문/재료 길잡이 8개·지역 6묶음·여름/겨울 2묶음·상황 3묶음이 같은 음식 ID를 참조한다. 월별 초안 전체 공개는 미완료이고 봄/가을은 보강 중으로 표시한다. 기존 지역·계절 필터, 홈 월별/PICK와 메뉴 단어장은 유지한다. 구형 MSBData 경로는 기존 화면을 그대로 사용한다.

음식 ID는 `reviewed.json.entries[].id`를 기준으로 고정한다. 예: `food_nonramen_gyudon`, `food_ramen_ramen`. 명칭·분류·사진을 바꿔도 사용자 marks/Plan/백업 저장 키를 바꾸지 않는다.

실제 옛 사용자 원고와 marks 표본의 전수 대응은 미완료다. 현재 카탈로그에는 확인되지 않은 옛 ID를 제목만 보고 자동 연결하지 않는다(`encMarksAlias`의 catalog 분기). 기존 MSBData끼리의 제목 복구 호환 동작은 별개로 유지한다. 미연결 기록은 삭제하지 않는다.

## 탐색 자료의 추가 계약

`catalog_schema: 1`은 유지하며 선택 필드 `discovery: {schema:1, guides:[], collections:[]}`를 추가했다. 각 안내는 고정 ID·제목·본문·`food_ids`·근거 구분·확인일·출처를 가진다. 음식/페이지 배열에 안내를 섞지 않아 개인 음식 기록을 복제하지 않는다. `reviewed.json.discovery_source`와 `discovery_sha256`으로 공개 원고를 고정하고 생성 시 참조·중복·URL을 검사한다. `discovery`가 없는 구형 카탈로그도 기존 음식 화면으로 읽는다. 개인 저장·백업 API와 `data-contract.json`은 그대로다.

## 원고 변경·생성·배포

1. 받은 원본을 설계 폴더에 별도로 보관한다. 기존 사용자 첨부를 덮어쓰지 않는다.
2. 공개 범위·사실 근거·ID·사진을 확인하고 `reviewed.json`의 해당 항목과 원본 항목 해시를 갱신한다. 해시 일치는 사실 검수를 대신하지 않는다.
3. 카탈로그를 생성하고 원본·참조·생성 결과를 검사한다.

```sh
python tools/encyclopedia_build.py
python tools/encyclopedia_build.py --check
python tests/data/test_encyclopedia_build.py
```

4. 실제 배포 Data를 바꿨다면 외부 명세를 갱신하고 확인한다. **`docs/`만 수정하면 카탈로그·명세를 재작성하지 않는다. 단, 이 README처럼 `Data/manifest.json`에 등록된 배포 문서는 문서만 바꿔도 명세의 크기·해시를 갱신해야 한다.**

```sh
node tools/data.js --write-manifest
node tools/data.js --check
```

5. 화면·저장 경로를 바꿨다면 해당 브라우저/백업 검증을 실행한다. 배포 전 이전 Data를 보관하고, 앱 종료 후 호환되는 Data와 manifest를 한 묶음으로 교체한다. 기존 개인 save/Maps/resources는 보존한다. 파일 구성·지원 형식 변경은 별도 호환성 검토가 필요하다.

자세한 계약: [외부 Data 배포 안내](../../docs/deployment/EXTERNAL_DATA.md). 사용자 표시·원고·백업 형식 변경이나 SQLite 전환은 이 절차에 포함하지 않는다.

## 월별 행사 묶음 (v0.95, 사장님 지시 2026-11-03)

계절 묶음(`kind: season`)에 선택 칸 `months`(1~12 정수 목록)를 둘 수 있다. 생성기는 달이 묶음 계절과 맞는지(봄 3~5·여름 6~8·가을 9~11·겨울 12~2) 검사한다. 앱 '계절·월별' 탭은 고른 달의 행사 묶음을 먼저, 그 계절의 일반 묶음을 이어서 보여 준다. v0.96 부터 열두 달 모두 묶음이 있다.

## 자세히 칸 (v0.96, 사장님 지시 2026-11-03)

원고 행의 선택 칸 `detail_ko`(`[{"title_ko","text_ko"}]`, 최대 6절)를 생성기가 본문 절로 넣는다. 제목은 '유래와 역사'·'언제 먹나'·'먹는 법'·'지역별 차이'를 쓴다. 유래는 알려진 설로 적고 단정하지 않는다. 사진 출처는 음식 사진 밑이 아니라 대백과 첫 화면 맨 아래에 모아 보여 준다(사진은 CC0·퍼블릭 도메인만).
