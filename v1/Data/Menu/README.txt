메뉴 읽기 화면(왼쪽 메뉴 '메뉴 읽기')과 음식점 상세 '메뉴 단어' 탭이 쓰는 단어 목록이다. 파일 하나(UTF-8).
프로그램을 빌드할 때 함께 들어간다(파일을 고친 뒤 다시 빌드).
서버가 시작할 때 검사해서 잘못된 단어·칸만 빼고 /api/menu-words 로 넘긴다. 파일 전체가 깨져도 앱은 멈추지 않는다
(화면에 '메뉴 단어를 불러오지 못했어요'만 나온다). 무엇이 빠졌는지: 개발판 화면 콘솔의 '메뉴 단어 검사' 경고,
또는 go test ./... (menu_words_test.go TestMenuWordsClean 이 경고 0개를 요구).
미식 대백과 용어집(MSBData)과는 별개다(대백과는 Codex 작업 — 나중에 링크로만 연결).

[맨 위]
  schema★   1
  updated   고친 날짜(메모)
  groups★   화면 분류 탭 [{"id": 영문 소문자, "label": 12자 이내, "icon": 이모지}] — 순서 그대로 탭에 나온다
  words★    단어 목록(아래). 순서 = 화면 순서

[단어 칸]  ★ = 필수
  ja★       메뉴에 쓰이는 대표 표기(30자 이내). 단어마다 한 번만
  kana      읽는 법(히라가나). ja 가 가나만이면 비워도 된다
  ko★       한국어 발음(예: 카에다마). 앱 표기에 맞춘다 — k→ㅋ, t→ㅌ, tsu→츠, g→ㄱ, 긴소리는 대개 줄인다(오모리·쇼유)
  mean★     뜻(60자 이내)
  group★    groups 의 id
  tip       알아두면 좋은 점 한 줄(160자 이내)
  alt       메뉴에 함께 쓰이는 다른 표기(가타카나·약자·붙여 쓰는 말 등, 2~30자, 12개까지)
  cats      이 말이 자주 나오는 가게 분류 — 도시 데이터(Data/City)의 기본 분류 대분류·세부분류 이름만(오타는 검사가 뺀다).
            음식점 상세 '메뉴 단어' 탭이 가게의 대분류·세부분류와 맞는 단어를 보여 준다
  cities    특히 이 도시에서 쓰는 말(도시 데이터의 도시 이름) — 카드에 표시만
  common    true = 어디서나 쓰는 말(상세 탭 '어디서나 쓰는 말'에 작은 칩으로 모두 — 그 가게 분류 단어와 겹치면 위에만)
  allergy·diet·dislike  내 미식 프로필과 연결(⚠ / 참고). 값은 Data/Taste/questions.json 의
            SAFETY_ALLERGY·SAFETY_DIET·SAFETY_DISLIKE 선택지(wheat·egg·fish·shellfish… / pork·beef·seafood·raw_food·alcohol… / offal…)

[붙여넣은 메뉴 글 풀이 규칙] (app_menu_words.js)
  · 글자 모양 통일(NFKC — 반각 가타카나·전각 숫자) 뒤, 단어의 ja·kana·alt 중 두 글자 이상만 찾는다(한 글자는 다른 말 속에서 잘못 걸림).
  · 같은 자리에서는 가장 긴 말을 먼저 고른다(たこ焼き 는 たこ 가 아니라 たこ焼き, 焼きそば 는 そば 가 아님).
    → 짧은 말이 긴 요리 이름 속에서 잘못 풀리면 그 요리 이름을 단어로 더한다(예: かき 굴 ↔ かき氷·かき揚げ).
  · 세 글자 이하 히라가나만(또는 가타카나만)으로 된 말은 앞뒤에 같은 종류 글자가 붙어 있으면 풀지 않는다
    (いかがですか 의 いか, いくらですか 의 いくら 는 그대로). '・' 는 구분 기호로 본다.
  · 같은 표기를 두 단어가 쓰면 검사가 경고한다(앞 단어로 풀이).
  · 내 알레르기·식이는 단어 연결(allergy·diet) 말고도 안전 낱말 목록(app_tags_collections.js SAFETY_WORDS)으로 한 번 더 본다.
  · 참고용이다 — 메뉴 안전을 보장하지 않는다(화면에도 같은 안내).

[주문 문장 Data/Menu/phrases.json] — v1.315, 로드맵 43
  words.json 과 같은 폴더에 두면 함께 읽어 /api/menu-words 응답의 order 로 넘긴다(없으면 주문 문장만 비고 경고 없음).
  schema★   1
  groups★   분류 탭 [{"id", "label", "icon"}] (words.json 과 같은 규칙)
  phrases★  [{"id": 영문 소문자(중복 금지), "ja": 일본어 문장★, "say": 한국어 발음★, "ko": 한국어 뜻★, "group"★, "tip", "cats"}]
            ja·say·ko 는 80자 이내, ja 에 한국어 금지. cats = 이 가게 분류에서 쓰는 문장(도시 데이터의 분류 이름) —
            음식점 상세에서 카드를 열면 그 가게 분류의 문장이 먼저 나온다(라멘 → 替え玉 등)
  names     내 알레르기·식이 카드에 쓰는 일본어 이름(미식 프로필 값 → 일본어)
            {"allergy": {"shellfish": "えび・かに・貝類", …}, "diet": {"pork": "豚肉", …}} — 대백과 주문 카드(ENC_ALG_JA)와 같은 말
  카드 문장 틀(app_menu_words.js mwSafetyLines): 〜のアレルギーがあります / 少しでも入っていると食べられません /
  〜は食べられません / 生ものは… / お酒（アルコール）は… / この料理に〜は入っていますか？ / 食べられるメニューを教えてください。
  메밀은 같은 물로 삶은 것, 돼지고기는 돈코츠 국물·라드 문장을 더한다. 직접 적은 '기타'(한국어)는 카드에 넣지 않는다.

  같은 음식의 한국어·일본어·로마자 이름 묶음. 저장한 음식점 검색('돈코츠'로 豚骨·とんこつ 가게도 찾기)과
  Google 검색창의 한국어 음식 이름 → 일본어에 쓴다(names.go). 이 파일에는 메뉴 단어·도시 음식에 없는 흔한 한국어 표현만 적는다
  — 메뉴 단어(words.json, 읽기로 로마자도 만듦)와 도시 데이터 음식 이름(Data/City)은 프로그램이 자동으로 합친다.
  schema★   1
  groups★   [{"ja": Google 검색에 쓸 일본어★, "ko": [한국어 이름★…], "alt": [다른 표기·로마자…]}]
            ko 는 한국어 20자 이내, alt 는 30자 이내·한국어 금지·한 글자는 한자만(鰻 O, と X — 다른 말 속에서 잘못 걸림).

TASTORY 음식점 목록(Data/Restaurants)을 읽을 때 서버가 쓴다(restaurant_terms.go). 목록 파일 자체는 바꾸지 않는다.
음식 이름 자체(모츠나베 ↔ もつ鍋)는 names.json 이 맡고, 여기는 가게 이름에 붙는 브랜드·일반 낱말만 맡는다.
시험: go test -run TestRestaurantBrandsTerms ./...

[brands.json — 고유명사형 브랜드(체인)]
  show★    화면 표기(한국에서 부르는 이름: KFC · 맥도날드 · 버거킹 …, 20자 이내)
  ja★      원래 이름에 이 말이 있으면 이 브랜드(대소문자·히라가나/가타카나·전각 무시)
  strict   true = 이름이 이 말로 시작하고 바로 뒤가 가타카나·로마자가 아닐 때만(ガスト ↔ ガストロ, 松屋 ↔ 小松屋)
  ko       한국어 이름(번역)이 이렇게 시작하면 show 로 바꿔 표기(켄터키 프라이드 치킨 텐진점 → KFC 텐진점)
  alias    검색에 더 쓰는 말(영문·줄임말: mcdonalds · 맥날 · 스벅)

[terms.json — 가게 이름의 일반 낱말]
  ja★      원래 이름에 이 말이 있으면(炭火 · 鉄板焼 · 割烹 …)
  ko★      한국어 표기(숯불 · 철판구이 · 갓포). 번역을 합칠 때(tools/restaurant_build.py --names) alt 표기를 이것으로 맞춘다
           — 띄어 쓴 낱말 전체가 alt 와 같을 때만 바꾼다
  alt      번역에서 나온 다른 표기(스미비 · 뎃판야키 …)
  search   검색에 더 쓰는 말(숯불 → 숯불구이, 개별실 → 룸·개인실)
  enc      미식 대백과에서 찾을 표제어(대백과 연결용 — 대백과 출시 데이터가 생기면 화면에서 '대백과에서 보기'로 연결)
